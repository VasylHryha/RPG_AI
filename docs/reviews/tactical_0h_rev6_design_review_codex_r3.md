## New and remaining findings

### 1. R3-1 — HIGH: F1 cannot instantiate its stated chains under C4

**Evidence:** R6:350–353 requires pure 1-, 3- and 5-link chains at r* with each receiver having only its predecessor as a neighbour, followed by free C4 motion. C4:71–79 selects up to eight nearest elements within strict radius 3; C4:105–111 holds those lists only within each RK4 step.

For a straight 3-link element chain at spacing 0.556, its four members span 1.668 m.u.; every pair is within radius 3 and every receiver has three neighbours. A 5-link chain spans 2.780 m.u.; its six members likewise form a complete neighbour graph. The predecessor-only condition cannot hold. A held/fixed phase topology could impose it, but that is a different projection, not the declared intact C4 fixture. A sensor site itself is an external drive, not a C4 element neighbour, so the source element also needs to be explicitly defined.

Further, if the chain extends directly from the sensor, all these nominally intermediate ordinary members lie in its drive reach unless their gains are explicitly zero. The output can receive phase coupling directly from a driven member near it. Such a fixture cannot establish the delay of a serial 3- or 5-link route, even if its output follows the step. Calling r* a hypothesis is correct; this fixture does not test that hypothesis as written.

**Fix:** register actual element positions, roles, gains, sensor drive/strength and initial phases; derive every neighbour list from intact C4. Record direct-drive exposure, actual link weights/counts and effective paths. Either describe these short configurations honestly as dense scaffolds testing output response, or construct a genuinely longer/non-shortcut configuration and freeze an achievable response criterion for it. If a predecessor-only transfer experiment is useful, label it a separate topology-controlled diagnostic and retain an intact-law transmission gate. Do not change frozen C4 or silently force lists to make F1 pass.

### 2. R3-2 — HIGH: the trial can shrink δ while disconnecting its chosen source

**Evidence:** R6:255–259 recomputes all lists, then condition 1 checks that a is in the newborn's list and concludes the newborn is in F_s. That conclusion requires a to remain reachable in the **post-insertion** graph. An insertion can remove a's incoming predecessor by changing its eight-nearest list. Condition 2 protects completed site-to-output paths, not an unfinished source frontier.

An analytic configuration illustrates that condition 3 does not repair this inference. Use a single effective root u = (−2.9,0), a = (0,0), and output b = (3.1,0). Put seven non-root distractors close to (1,2.72), each at distance below 2.9 from a, and dense non-root padding just outside radius 3 from a near (1,2.85). The padding lets each distractor select eight nearby cluster members instead of a. Give only u positive drive gain, with its active sensor at (−4,0). Thus initially F_s = {u,a}, T = {b}, a selects the seven distractors and u, and δ_s = 3.1. The cluster is more than 3 from b and u. Small coordinate perturbations preserve these strict inequalities; coincident elements are unnecessary.

The prescribed candidate is c = (0.556,0). It selects a and b among its eight neighbours, while a replaces u with c. The output selects c. Hence c → b and c → a make a backward-reaching, but u no longer reaches a or c. Post-trial F_s = {u}; T includes a, c and b. The gap decreases to 2.9, and no previously completed site path is lost because there was none. Clearance and the listed edge check pass, yet c is **not** forward-reachable from the intended root. Copying θ_a supplies an initial phase, not ongoing root influence. This counterexample is not a simulation or an attainability claim about a particular trained seed.

**Fix:** explicitly test `newborn ∈ Reach(post_trial_roots_s, post_trial_graph)` in addition to the actual a → newborn edge, preserved required paths and the post-trial deficit rule. If preservation of a itself is intended, test that too. Rejection must restore the entire trial state before another candidate is tried. Register a saturated-receiver counterexample of this form for the later authorized batch. A second birth sometimes repairing the damage does not make the first acceptance valid.

### 5. R3-5 — MEDIUM: G2-sel can reward avoiding empty sites without task-relevant selection

**Evidence:** R6:344 interprets a positive bound against physical site 0 as “showing selection beyond a fixed relay.” That comparison can reward an arbitrary-item relay which simply routes the lowest-id **active** physical site, without comparing strengths or identifying the nearest enemy. Site 0 instead emits the default whenever it is inactive.

At the initial perceive frame, the active-site relay routes a uniformly assigned enemy among K, so its expected angular error is `(1 − 1/K)·π/2`. The site-0 relay's expected error is `7π/16`: the truth occupies site 0 with probability 1/8, and wrong-item/default angles have expected error π/2 (world source: `world/world.cpp:75–108,115–118,164–167`; base:51). For K < 8 the active-site relay improves this expectation without salience-based selection. This is an analytic initial-frame example, not a measured full-episode PASS. It identifies an alternative mechanism the comparator does not isolate. Superiority to the fixed relay is a valid performance statement; “selection” needs to say whether mere avoidance of empty sites counts.

This also tightens my round-2 suggestion: a fixed-site comparator with inactive-site defaults does not exclude the entire arbitrary-item-routing explanation. Primary G2's narrowed input-dependent-response claim is sound and needs no stronger selection gate.

**Fix:** label this diagnostic exactly as superiority to the site-0 relay, with task-relevant selection unqualified. If a stronger selection diagnostic is retained, define selection and predeclare a comparator covering arbitrary active-item routing under the same exposure/decoder, with its inference rule. Do not pick the comparator from the evaluated medium or panel outcomes. Keep that extension descriptive or propose it separately; do not enlarge primary G2 merely to answer this note.
