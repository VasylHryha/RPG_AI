The native engine checks `time >= duration` before each tick and advances with `nextTime = time + dt`. Repeated double addition at 30 Hz reaches the 150-second boundary on tick 4,501 (approximately 150.03333333332736 seconds), rather than a rounded `ceil(duration/dt)` count. Stage A's metric copy computes that same last permitted clock value from the sealed request's duration/dt. It additionally requires contiguous observer steps/times and terminal agreement, and keeps the existing completeness, 50v50, duplicate-terminal, survivor, host-error and finite/positive-time checks. The recorded end time is preserved for rate calculations. Rev2's original 150+1e-6 check and committed behavior are untouched.

The default O dataset uses length-prefixed binary numeric records inside a streaming LZMA preset-1 container. Arrays preserve IEEE-754 float64 bits, including their exact bitwise XOR deltas from previous arrays of the same row family. There is no float32 rounding. Numeric fields are laid out by columns; the reader restores the same policy `pack`, label/mask, audit, training and native replay APIs. The writer bounds the pending host row and the reader bounds each record to 4 MiB; host stdout still has its existing 1 GiB/fight bound. Failed compressed attempts remain readable evidence with their own random attempt IDs.

All public units, own resources, four threat banks, timestamps, dt, identities, public-history features and pair modes are retained at every physical tick. Executed goals/targets/multipliers/fire/aim, aim masks, role, readiness, active reaction and engine-release labels are retained. The current policy uses fresh queries and advances learned state at every physical tick; only the shared encoder refreshes at 5 Hz and on identity changes. Keeping the full physical input sequence avoids changing those semantics and supports native float64 sequence parity. Network/parity fixtures and outcomes keep full-detail recording; `collect.py diagnostic --tag <sealed-job-tag>` allows at most three separately named full-detail attempts, outside the training index, without changing a sealed request.
