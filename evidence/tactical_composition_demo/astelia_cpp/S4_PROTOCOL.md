# S4 development protocol, declared before any tuning fight

Owner-authorized exploration under decision 0028 and S4_DEVELOPMENT_REQUEST_CODEX.md. No registration, judging seeds, or S5 verdict. Controller equations and bounds are DESIGN_0G.md revision 3 sections 3–5, unchanged. S3 engineering is APPROVE_WITH_NOTES.

Expected execution: **10–20 minutes** for tuning and validation using eight native workers (S3 stateful full fights measured ~0.55 seconds). This is an estimate; record actual time. Complete code and test edits before execution. No code edits while fights run.

Stages: A = 10 melee against 10 melee, novice. B = 10/30/10 full armies, novice and regular equally. C = full armies, all 19 doctrines equally over the stage (rounds cycle through the ordered pool). The opponent uses exactly the elite catalog skills with artyRollout=null and lookahead=null, preserving each doctrine. Controlled skills, Auto abilities, game rules, perception=false, mirror, duration=150 and dt=1/30 are fixed. Named settings are written in every fight log.

All three tuned arms use the same algorithm: eight rounds per stage; eight new candidates around the incumbent each round. Begin A at contract midpoints; begin B and C at preceding stage best. For each candidate choose with probability 1/2 either all knobs or one uniformly chosen knob. Each chosen knob is sampled uniformly inside its bound intersected with incumbent ± r times the bound width, r = 0.5 × 0.8^round (reset each stage). Python Random with arm/stage-specific recorded seeds 510050 + 100×stage_index + arm_index (indices resonator/morale/pushpull=0/1/2). Resonator's nonzero role rates are sampled by this procedure.

Each round uses 32 new development clusters and evaluates the incumbent on all 32. Evaluate eight candidates on the first eight clusters, keep four by highest mean S (stable candidate index ties), extend those to sixteen, keep two, extend to thirty-two. Ranking elimination is a search heuristic, not a statistical claim that eliminated candidates are inferior. Accept at most one finalist: greatest mean S among those with paired cluster gain > max(1 survivor, 2 SE). Gain and SE use key-joined candidate-minus-incumbent cluster differences, with sample SD divided by sqrt(n). Both orientations constitute one cluster. This retains compose's default MIN_GAIN=1. Every candidate records knobs, evaluated scores, fights, acceptance/rejection or failure. No D tiebreaker.

Budget: incumbent 64 fights + eight candidates ×16 + four ×16 extra + two ×32 extra = **320 fights per round**, **2,560 per stage**, **7,680 per tuned arm**. Cache hits count. Ranking always retains fixed counts, ensuring equal budgets. Nearest is untuned. Anomaly, validation and replay exports are separately counted and never influence candidate acceptance. Replays repeat designated validation fights for capture; their summaries must match the original. This does not count as new statistical evidence.

Validation is separate: A 32 clusters against novice; B 32 per head level; C 16 per doctrine and 32 against each head level on a fresh split. Carry only tuning-selected knobs between stages; validation does not select knobs, change budget or retune. After the full budget, final resonator novice mean S≤0 triggers STOP. A/B losses are diagnostics during the allocated development stages, not the final stop assessment.

Before tuning: investigate morale on eight matched seeds × two orientations across novice/regular and a 2×2 brain/skill diagnostic (novice skills + line formation, regular skills + alone). These are fixed diagnostic settings, not new arms or controller knobs. Export one chosen fight from each configuration; inspect trajectories before tuning. Export one chosen validation fight per arm per stage afterward.

Report validation means, cluster SD, SE and descriptive normal 95% mean intervals. SD uncertainty uses 2,000 bootstrap resamples with fixed RNG 811005, 95th percentile. Propose δ = max(1, 0.25×maximum pooled paired SD of P2/P3), rounded UP to 0.5 survivors. Owner approval is required; never lower δ to pass. Power planning: one-sided alpha .0025, power .90, normal approximation. P1 plans to detect δ above zero; P2/P3 plan a true advantage 2δ against margin δ. For equal-weight doctrine inference, variance = sum(within-doctrine SD_upper²)/19²/n_per_doctrine. Choose at least 32 clusters per head and 16 per doctrine. Above 2,000 total clusters per endpoint, report the tradeoff for the owner; do not silently truncate. These are planning estimates, not a final inference specification. Report observed tuning spreads alongside independent validation; final n uses validation to avoid selected-candidate gain noise.

Controller failure: log raw failure, stop execution, fix first and restart the affected arm's entire budget. Outcome-informed equation change: log and restart that arm. Contract conflict: report the question, do not silently resolve it. No fresh judging entropy is generated by this harness.
